# Отчёт об успешном тесте

Фактические результаты нашего эксперимента.

Здесь собраны проверенные данные. Личные идентификаторы удалены.

---

## 1. Устройство

| Параметр | Значение |
|---|---|
| Устройство | Яндекс Станция Мини 2 |
| Вариант | Без часов |
| Модель | YNDX-00021 |
| Платформа | `yandexmini_2` |
| ADB-порт | 5555 |

Тестировалась одна колонка. Другие модели не проверялись.

---

## 2. Исходная прошивка

В журнале была указана версия:

```text
0.17.1.32.1145264292.20211203.factory-3.FACTORY.factory
```

Это заводская версия прошивки. Именно её передавала колонка.

Эта версия относится к тесту. Она не обязательна другим устройствам.

---

## 3. Целевая прошивка

Для теста выбрали версию:

```text
0.369.1.46.4778262943.20261013.299
```

Платформа указана отдельно:

```text
yandexmini_2
```

Файл имел следующие параметры:

| Параметр | Значение |
|---|---|
| Имя | `0.369.1.46.4778262943.20261013.299.zip` |
| Размер | 67 796 480 байт |
| CRC32 | `1524631406` |
| SHA256 | `192aa9842c77257c4955c9a02cea837f91217d25206d2368815700280ab3c8c3` |

### Загрузка файла

Использовался установщик lite-kit.

```bash
./install-firmware.sh -p yandexmini_2
```

Затем выбрали нужную версию. Тогда это был пункт 20.

Номер пункта не постоянный. Выбирайте по полному номеру версии.

Установщик создал ZIP и манифест. CRC32 совпал с ожидаемым значением.

SHA256 проверялся отдельно. Он также совпал.

---

## 4. Подготовка стенда

В рабочем каталоге были флаги:

```text
run/downgrade
run/no_downgrade.disabled
```

Защитный маркер был отключён. Режим даунгрейда был включён.

В ходе эксперимента менялся DNS-шаблон. Также менялся запускной скрипт.

### Изменения DNS

Вместо стандартных пересылок использовались серверы AdGuard DNS.

```ini
server=94.140.14.14#53
server=94.140.15.15#53
#server=77.88.8.8
server=/iot.quasar.yandex.net/94.140.14.14
```

Это было сетевое решение. Оно зависело от окружения.

Его нельзя считать обязательным. Сначала проверьте стандартные DNS.

### Изменения start.sh

В локальной копии добавили `LOCAL_IP`. Это позволило задавать IP явно.

Текущий lite-kit уже поддерживает это. Старые версии могли отличаться.

---

## 5. Первые попытки OTA

Сначала прошивка не находилась. Сервер отвечал `hasUpdate:false`.

В журнале появлялось сообщение:

```text
[OTA] прошивки нет для этой модели
```

После подготовки файла сервер начал выдавать OTA-манифест.

Появилась строка `OTA-AUTO`. В ней была целевая версия.

Колонка запрашивала `check_updates`. Сервер отвечал кодом 200.

---

## 6. Передача прошивки

Колонка запросила ZIP-файл.

Путь содержал `yandexmini_2`. Имя содержало целевую версию.

В журнале появилась строка:

```text
[OTA] файл отдан ПОЛНОСТЬЮ (67796480 б)
```

Следующая строка содержала диапазон байтов:

```text
bytes 0-67796479/67796480
```

Это подтверждает полную отдачу файла. Размер совпал с ожидаемым.

После обновления колонка сообщила новую версию. Повторный OTA больше не предлагался.

Сервер вернул `hasUpdate:false`. Это было ожидаемое поведение.

---

## 7. Синхронизация и ADB

После OTA появился запрос Sync.

Запрос содержал целевую версию. Платформа оставалась `yandexmini_2`.

Сервер получил ответ Яндекса. Исходный ответ занимал 12 262 байта.

В исходном ответе ADB отсутствовал. Это показала строка `SYNC-NATIVE`.

Затем сервер добавил параметры ADB. Изменённый ответ имел 13 293 байта.

В журнале были отметки:

```text
config.system_config.adbd=on
config.system_config.adbd.network=on
config.device_config.adbd=on
config.adbd=on
top.adbd=on
```

Это подтверждает инъекцию параметров. Колонке был отправлен обработанный Sync.

---

## 8. Ответы 429

Во время синхронизации встречался HTTP 429. Он возникал на `set_device_capability`.

Стенд повторял запросы. В журнале видны повторы.

После них был получен ответ 200. Процедура продолжилась штатно.

Этот эпизод не подтверждает Root. Он описывает только обработку ошибки.

---

## 9. Проверка Root

После синхронизации проверили порт 5555. ADB стал доступен по сети.

Подключение прошло успешно. Затем выполнили команду `id`.

Получен результат:

```text
uid=0(root) gid=0(root)
```

Это прямое подтверждение Root. Команда выполнена от суперпользователя.

IP-адрес колонки не публикуется. Идентификаторы устройства также удалены.

---

## 10. Что подтверждено

- Модель YNDX-00021.
- Платформа `yandexmini_2`.
- Переход на целевую прошивку.
- Полная передача OTA-файла.
- Получение обработанного Sync.
- Включение сетевого ADB.
- Подключение к порту 5555.
- Получение `uid=0(root)`.

---

## 11. Что не подтверждено

Сохранение Root после перезагрузки. Сохранение ADB после перезагрузки.

Работа на YNDX-00020. Работа на других моделях.

Работа на других прошивках. Восстановление после неудачной OTA.

Эти проверки не выполнялись. Не делайте выводов заранее.
